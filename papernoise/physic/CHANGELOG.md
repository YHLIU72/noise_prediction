## V10 失败分析 (2026-06-14)

### 实验设计
- 假设: 20~60Hz 验证集 RMSE~2.8dB 是 100Hz+ 的 2.2×, 截去应降低整体 MSE
- 操作: `parsed[5:1251]` → `parsed[15:1251]`, freq_bins 1246→1236

### 实验结果
| 指标 | V4 (20~5000Hz) | V10 (60~5000Hz) | 变化 |
|------|---------------|-----------------|------|
| val_mse_db (best) | 2.059 | 2.232 | ⚠️ +8.4% |
| val_total (best) | 11.828 | 12.417 | +5.0% |
| 过拟合 (val恶化%) | +19% | +31% | ⚠️ 更快 |

### 根因分析
1. **统计贡献微不足道**: 10 bins/1246=0.8%, 理论MSE上限改善仅3.8%
2. **低频段是频谱锚点**: 20-60Hz能量最高(60-80dB), 去掉后模型失去绝对水平参考
3. **数据增强边界伪影**: `np.roll` 把高频低能值循环到60Hz边界, 产生不真实频谱
4. **freq_proj 层需重学**: 最后一层 Linear(512,1236) 权重随机初始化, 从零学习代价大
5. **中间表示未优化**: 1024维中间特征原为1246频点设计, 无法自动适配新分布

### 结论
**截断数据不是解决低频误差的正确方法。** 应通过损失函数引导、架构增强或采样策略来提升低频精度。

## V11~V13 三方案对比 (2026-06-14)

### 方案概览

| 方案 | 版本 | 核心思路 | 模型改动 | 数据改动 |
|------|------|---------|---------|---------|
| 方案1 | **V11** | 频率加权损失 | 损失函数加 `freq_weights` | 无 |
| 方案2 | **V12** | 低频专项Head | 新增 `LowFreqBranch` + 残差融合 | 无 |
| 方案3 | **V13** | 对数频率重采样 | 无 | logspace 插值重采样 |

### V11: 频率加权损失

```
w(f) = (5000/f)^0.3, 归一化到均值=1.0
20Hz权重≈2.5× | 100Hz≈1.6× | 1000Hz≈0.8× | 5000Hz≈0.5×
```

**设计理念**: 不去掉低频段，而是让损失函数"更关注"低频。梯度自然引导模型优先学好低频形状。

**Loss 组成**: `5×WeightedMSE + 2×LinearPeak + 3×Grad`

**TensorBoard 新增指标**: `train_mse_raw`, `val_mse_raw` (未加权纯MSE, 用于对比)

**文件**:
- `PIMBCN_net0614_v11.py` — 网络 + 频率加权 PhysicsLossWrapper
- `PIMBCN_data_0614_v11.py` — 同 V4
- `PIMBCN_train0614_v11.py` — 训练脚本 (记录加权/未加权双MSE)

### V12: 低频专项Head

```
解码器特征 [B,8,1024]
    ├→ SharedHead → 全频段预测 [B,1246]
    └→ LowFreqBranch → 低频残差 [B,50]  (20~200Hz)
         └→ 残差融合: pred[:50] += low_residual
```

**设计理念**: 在统一预测基础上，增加专门处理低频的分支。大卷积核(kernel=15)捕获低频宽泛结构。

**Loss 组成**: `5×MSE + 2×LinearPeak + 3×Grad + 2×LowFreqMSE`

**新增参数**: ~135K (低频分支), 总参数 ~1.77M

**文件**:
- `PIMBCN_net0614_v12.py` — 网络 + LowFreqBranch + 低频损失
- `PIMBCN_data_0614_v12.py` — 同 V4
- `PIMBCN_train0614_v12.py` — 训练脚本 (记录低频MSE)

### V13: 对数频率重采样

```
V4线性采样: [20, 24, 28, ..., 5000] — 1246点等间距
V13对数采样: logspace(log10(20), log10(5000), 1246)
  → 低频(<100Hz): ~150点 (V4的7.5×)
  → 高频(>1000Hz): ~400点 (V4的53%)
```

**设计理念**: 不改变模型，只在数据端用对数坐标重采样。低频获得更高"有效分辨率"。

**实现**: `np.interp(log_freqs, linear_freqs, spectrum)` 在预处理阶段完成

**文件**:
- `PIMBCN_net0614_v13.py` — 同 V4
- `PIMBCN_data_0614_v13.py` — 对数频率重采样数据加载
- `PIMBCN_train0614_v13.py` — 同 V4

### 一、模型架构变更

#### 1.1 解码器瘦身
| 项目 | 0601 原版 | 0610 final |
|------|----------|------------|
| 转置卷积层数 | 7 层 | **6 层** |
| 输出形状 | `[B,4,2048]` | `[B,8,1024]` |
| 中间维度膨胀比 | 256→8192 (32×) | 256→8192→**4096 (16×)** |

**理由**: 原版从 256 维膨胀到 8192 维再缩到 1246 维，中间沙漏太宽，1024 维对 1246 点输出更匹配，降低过拟合。

#### 1.2 任务头渐进投影
| 项目 | 0601 | 0610 final |
|------|------|------------|
| freq_proj | `Linear(2048, 1246)` | `Linear(1024,512)` + `Linear(512,1246)` |
| 参数量/head | ~255 万 | ~117 万 (**↓54%**) |

**理由**: 52 个独立 head × 平均 21 条训练数据/head，直接大矩阵投影极易过拟合。

#### 1.3 BatchNorm → InstanceNorm
```
TransposeConvBlock: BatchNorm1d → InstanceNorm1d
```
**理由**: batch_size=8 下 BN 统计量噪声大（每个通道仅 8 个样本）。IN 逐样本独立归一化，不受 batch 影响，在小批量生成模型中为行业标准做法。

#### 1.4 频谱频率范围
```
2501 点 (0~10000Hz @4Hz) → 1246 点 (20~5000Hz @4Hz)
切片: parsed[5:1251]
```

### 二、损失函数重构 (V2)

#### 2.1 移除的损失项

| 移除项 | 原因 |
|--------|------|
| **Cosine 相似度** (原 weight=1.5) | dB 值全正 (20~80dB)，所有向量方向高度相似，cos 值 0.95~1.0，梯度≈0 |
| **LogMSE** (原 weight=1.5) | dB = 20·log10(P/Pref) 已是对数域；log(dB) = log(log(P)) 双重对数无物理意义 |
| **OASPL** (原 weight=1.0) | OASPL 从频谱派生，MSE 最小化后 OASPL 自然接近；单独损失项冗余且产生梯度冲突 |

#### 2.2 新增损失项

| 新增项 | weight | 公式 | 作用 |
|--------|--------|------|------|
| **线性峰值 MSE** | 2.0 | `MSE(10^(dB/20), 10^(target/20))` | dB→声压比，自动侧重高峰值（60dB处误差≈100×于20dB处） |

#### 2.3 调整的损失项

| 调整项 | 0601 | 0610 final | 理由 |
|--------|------|------------|------|
| dB-MSE | 7.39 | **5.0** | 降低以避免 mse 主导 |
| Sobolev 梯度 | 2.72 | **3.0** | 增强频谱平滑约束 |

#### 2.4 最终损失组成

```
Total = 5.0 × dB-MSE + 2.0 × LinearPeak + 3.0 × Sobolev
```

### 三、训练策略优化

#### 3.1 EMA (指数移动平均)
```python
ema_model = deepcopy(model)  # 平滑模型, 不参与训练
ema_p = 0.999 × ema_p + 0.001 × model_p  # 每个 step 更新
```
- 验证用 EMA 模型 (泛化能力更强)
- 保存的是 EMA 权重
- **预期降低验证损失 2~5%**

#### 3.2 LR warmup
```python
前 5 epoch: lr 从 0 线性升至 3e-4
```
**理由**: AdamW 初始动量未建立，直接 3e-4 的 lr 会导致早期梯度震荡。

#### 3.3 调度器调整

| 参数 | 0601 | 0610 final |
|------|------|------------|
| `T_0` | 20 | **150** |
| 首周期步数 | ~2,700 | **~16,200** |
| **LR warmup** | 无 | **前5 epoch** |

#### 3.4 DataLoader 优化
```python
num_workers=2, persistent_workers=True
```
- 加速 CPU 端数据增强
- 减少 GPU 等待时间

#### 3.5 超参数调整

| 参数 | 0601 | 0610 final | 理由 |
|------|------|------------|------|
| lr | 5e-4 | **3e-4** | 小样本更稳定 |
| weight_decay | 5e-3 | **1e-3** | 避免过度压缩参数 |
| batch_size | 8 | 8 | 不变 |
| epochs | 50000 | 50000 | 不变 |
